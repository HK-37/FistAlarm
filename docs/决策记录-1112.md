## 决策 1 & 2:注册表 Run 键,且以它为唯一真相

- **当时的问题**:久坐提醒不开机自启基本没用,设计文档一开始就列了"带开机自启开关(写注册表 Run 键)"。
- **否掉的方案**:① 启动文件夹放快捷方式——还要生成和清理 .lnk,更麻烦;② 自启状态另存进 alarms.json 再和注册表同步——两处容易不一致。
- **结论**:写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `FistAlarm` 值;开关状态直接读"这条值在不在",不另存。
- **理由**:**AI 判断**(方向来自设计文档)。HKCU 不需要管理员权限。单一真相避免同步 bug。
- **代价与可逆性**:只对当前 Windows 用户生效(符合预期)。易逆(取消即删值)。
- **实现位置**:`fistalarm/autostart.py`

## 决策 3:勾选即时生效

- **结论**:管理界面设置条加勾选框,勾上/取消立刻写/删注册表,不走"保存"按钮。失败则勾选回弹并提示。
- **理由**:**AI 判断**。自启是注册表这一处操作,即时生效比"改完再保存"更直觉。
- **实现位置**:`fistalarm/ui/manager.py:get_autostart/set_autostart`、`manager.html`

## 决策 4:每次开启都写当前 exe 路径

- **结论**:`enable()` 总是写当前 `sys.executable`,而不是"已开就跳过"。
- **理由**:**AI 判断**。exe 换过位置后重新勾选能刷新成新路径,避免开机启动的是旧路径的死 exe。
- **实现位置**:`fistalarm/autostart.py:AutoStart.enable`

## 本期做 / 不做

**做**:开机自启(注册表读写 + 管理界面开关);11 个新测试(共 199 个);真实注册表读写在本机验过一轮(临时值名,验完清理)。

**不做**:全局(所有用户)自启;开机延迟启动;自启后静默不弹任何东西的选项。

⚠️ **风险留痕**:自启写的是当前 exe 的绝对路径。如果用户把 exe 移动或删除后没取消自启,开机会尝试启动一个不存在的路径(Windows 静默忽略,无害);重新勾选可刷新路径。
