## 决策 1:只检查提醒,不自动替换

- **当时的问题**:用户想给 exe 加自动更新升级。
- **否掉的方案**:全自动下载新 exe、等旧进程退出后替换并重启。
- **结论**:只做检查 + 托盘提醒,点击后用浏览器打开下载页,由用户手动下载。
- **理由**:**AI 判断,用户采纳**("着手把检查更新相关的能力加上")。运行中的 exe 在 Windows 上不能覆盖自己,需要额外的替换进程和失败回滚;"程序自己下载 exe 再替换自己"容易被安全软件拦截(推测,未实测);exe 没有代码签名,每个新版本都可能触发 SmartScreen 提示。
- **代价与可逆性**:用户要手动下载新版。以后需要时可在此基础上加自动替换。
- **实现位置**:`fistalarm/updater.py`、`fistalarm/tray.py:TrayApp.run_update_check`

## 决策 2:不用 GitHub API

- **当时的问题**:怎么知道最新版本是多少。
- **否掉的方案**:调用 `api.github.com/repos/.../releases/latest`。
- **结论**:请求 `https://github.com/HK-37/FistAlarm/releases/latest`,不跟随跳转,从跳转地址里取 tag。
- **理由**:**AI 判断,有实测依据**。在公司网络里调用 API 直接返回 `API rate limit exceeded`:匿名调用每个 IP 每小时只有 60 次,公司出口 IP 是共用的。网页跳转不受这个限制,实测可用。
- **代价与可逆性**:依赖 GitHub 网页的跳转行为;如果 GitHub 改了行为,`fetch_latest_location` 会退化为返回最终地址,检查结果变成"已是最新"或"检查失败",不会误报。
- **实现位置**:`fistalarm/updater.py:fetch_latest_location`

## 决策 3:检查时机与提醒规则

- **结论**:启动 30 秒后自动查一次,之后每 24 小时一次。自动检查只在发现"没提醒过的新版本"时弹通知,没新版或失败时不打扰;手动"检查更新"不论结果都告知。网络失败归为"检查失败",不会误报"已是最新"。
- **理由**:**AI 判断**。启动时延迟一下,避免和开机时其他程序抢网络。
- **实现位置**:`fistalarm/tray.py:TrayApp.start_update_checker` / `run_update_check`

## 决策 4 & 5:版本号单一来源,升到 0.2.0

- **当时的问题**:版本号原来在 `__init__.py` 和 `pyproject.toml` 各写一份;检查更新依赖它,两处容易改漏。
- **结论**:`pyproject.toml` 改成 `dynamic = ["version"]`,从 `fistalarm.__version__` 读取。新增功能,版本升到 0.2.0。
- **理由**:**AI 判断**。
- **实现位置**:`pyproject.toml`、`fistalarm/__init__.py`

## 决策 6:手动检查改用消息框

- **当时的问题**:用户点"检查更新"两次都反馈"没有任何反应"。
- **排查经过**:
  1. 先确认运行的是新打包的 exe(进程启动时间晚于打包时间)。
  2. 源码中起真实托盘、程序模拟点击:菜单状态行 1 秒内更新为"已是最新",逻辑正常。
  3. 用打包后的 exe 跑 `--check-update`:联网正常,拿到 v0.1.0。
  4. 加 `tray.log` 后请用户实点:日志显示 3 次点击都收到、检查都成功、刷新菜单和发通知都没报错。
  5. 起测试托盘发弹窗通知并截屏:调用不报错,但屏幕上没有任何弹窗——托盘库在 Windows 上用的是老式气泡通知,在用户的 Win11 上不显示(原因推测,未深挖)。
- **否掉的方案**:① 只在菜单里加状态行(用户点完菜单就关了,要再右键才看得到,实测仍被认为"没反应");② 引入第三方 Win10/11 通知库(加依赖,且同样可能被系统策略拦截)。
- **结论**:手动检查一律弹 Windows 自带的置顶消息框;有新版时是"是/否"对话框,点"是"打开下载页。自动检查不弹框,只更新菜单(有新版时出现下载入口),并尝试发弹窗通知。
- **理由**:**AI 判断,用户实测确认"没问题了"**。消息框是系统原生窗口,交付前已在用户电脑上弹出并截屏确认可见。
- **代价与可逆性**:消息框是模态的,但只阻塞检查更新的后台线程,不影响托盘和闹钟。易逆。
- **实现位置**:`fistalarm/tray.py:win_message_box`、`TrayApp._show_manual_result`

## 决策 7:托盘日志与命令行诊断

- **当时的问题**:exe 打包时关闭了控制台,后台线程里的异常不会出现在任何地方,出问题时外面只能看到"没反应"。
- **结论**:新增 `%APPDATA%\FistAlarm\tray.log`,记录检查更新的点击、过程、结果与报错;检查过程中的任何异常都转成菜单上的"检查失败(原因)"。新增 `--check-update` 参数,不开托盘直接跑一次检查并写日志,用于验证打包后的 exe。
- **顺带修复**:部分测试没把日志重定向到临时目录,跑测试时把假的检查结果写进了用户真实的 `tray.log`。新增 `tests/conftest.py`,所有测试的托盘日志自动写到临时目录;用户日志中的测试数据已清除。
- **理由**:**AI 判断**。
- **实现位置**:`fistalarm/tray.py:tray_log`、`fistalarm/__main__.py:_run_check_update`、`tests/conftest.py`
